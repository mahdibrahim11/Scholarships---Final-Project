## Other behaviours checked in the same run

- Opening admin URLs directly while logged out: redirect to login, no admin content in the response, and return to the page after sign-in. Off-site `next` targets are ignored.
- AJAX calls get JSON: 401 when logged out, 403 when the role is wrong.
- Menu by role (visitor, student, parent, administrator, Super-admin) and no development banner for anyone.
- Registration: server-side validation, CSRF, tampered roles (administrator, super_admin, visitor) refused, duplicate email refused, password stored hashed.
- Login: same message for unknown email and wrong password, session id regenerated, HttpOnly and SameSite cookie, planted session id rejected, logout is POST + CSRF, 5 failures lock the email for 15 minutes.
- Role changes and deactivation apply on the next request. A reset password forces a change and ends the person's other sessions. Idle past the timeout signs out; activity keeps the session alive.
